# Self-hosting Recalfy

```bash
npx recalfy
```

That is the whole install. This page covers what it does, and what to do when
you want something different.

## What setup does

1. Checks that Docker is installed and running.
2. Asks for your bot token and checks it with Telegram.
3. Asks which AI provider you use, and sends the model one test message so a
   wrong key or model name fails now rather than on your first message.
4. Waits for you to message the bot. Whoever sends that message becomes the
   **owner**, the only person the bot will talk to. Anyone else who messages
   it gets one line saying it's private.
5. Writes `~/.recalfy/.env` (readable only by you) and `~/.recalfy/compose.yml`.
6. Downloads the image, starts the bot and a MongoDB container, and waits
   until it's healthy.

Running `npx recalfy` again goes through setup again and keeps anything you
added to `.env` by hand. Your memory lives in a Docker volume and is never
touched by setup.

## Choosing a model

The bot saves facts and sets reminders by **calling tools**, so the model has
to be good at tool calling. A model that answers in prose will cheerfully say
"got it" and save nothing.

| Provider | Model to start with | Notes |
|---|---|---|
| OpenAI | `gpt-5-mini` | Reliable, a few dollars a month for one person |
| OpenRouter | `openai/gpt-5-mini` | One key for hundreds of models |
| Z.ai | `glm-5.2` | What recalfy.com runs; cheap |
| Ollama | `qwen3:8b` or larger | Free and private. Small models forget to call tools |

To switch later, edit `LLM_BASE_URL`, `LLM_API_KEY` and `LLM_MODEL` in
`~/.recalfy/.env`, then run `npx recalfy restart`.

**Ollama:** the bot runs in a container, so it reaches Ollama on your machine
at `http://host.docker.internal:11434/v1`, which setup fills in. On Linux,
Ollama must listen on more than loopback: `OLLAMA_HOST=0.0.0.0 ollama serve`.

## Backups

```bash
npx recalfy backup                 # → ~/.recalfy/backups/recalfy-<date>.archive.gz
npx recalfy restore <file>         # replaces the current database with the backup
```

A nightly backup with cron. Cron runs with an almost empty `PATH`, so give it
the full path to `npx`, which `which npx` prints:

```cron
0 3 * * * /usr/bin/npx --yes recalfy backup >/dev/null 2>&1
```

`npx recalfy export` prints your memory as Markdown, and `--json` includes
corrections, forgotten facts and reminders. `-o file` writes it to a file.

## Updating

```bash
npx recalfy update
```

It downloads the newest image and restarts the bot. Your data and settings
are kept.

## Moving to another machine

```bash
npx recalfy backup -o recalfy.archive.gz     # old machine
npx recalfy                                  # new machine: same bot token
npx recalfy restore recalfy.archive.gz       # new machine
```

Copy `MEMORY_ENCRYPTION_KEY` from the old `~/.recalfy/.env` into the new one
before restoring. Passwords and PINs you have told the bot are encrypted with
it, and a backup restored under a different key keeps them hidden for good.

Stop the old install first (`npx recalfy stop`). Two installs polling one bot
token fight over messages, and the logs will say so.

## Where things live

| | |
|---|---|
| `~/.recalfy/.env` | your settings and keys, including the one that encrypts saved passwords — back it up (`RECALFY_HOME` moves the folder) |
| `~/.recalfy/compose.yml` | the stack; regenerated by setup, so don't edit it |
| `~/.recalfy/backups/` | backups |
| Docker volume `recalfy_mongo-data` | your memory |

## Without the CLI

If you'd rather use plain Docker Compose from a checkout:

```bash
cp .env.example .env    # fill in TELEGRAM_BOT_TOKEN, OWNER_TELEGRAM_ID, LLM_*
docker compose -f compose.selfhost.yml up -d --build
```

## Troubleshooting

**The bot doesn't answer.** Run `npx recalfy logs`.
- `getUpdates failed: … 409`: another copy of the bot is running with the same
  token, possibly on another machine.
- `401` from the model: the key is wrong or has run out of credit.
- `Dropped update from unlinked sender`: someone other than the owner messaged
  it. If that was you from a second account, set `OWNER_TELEGRAM_ID` to that
  account's id and restart.

**Reminders arrive at the wrong time.** Tell the bot where you are ("I'm in
Berlin"), or set `DEFAULT_TIMEZONE` before your first message.

**Permission denied talking to Docker (Linux).** Run
`sudo usermod -aG docker $USER`, then log out and back in.
